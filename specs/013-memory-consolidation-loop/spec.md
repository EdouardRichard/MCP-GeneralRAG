# Feature Specification: 记忆巩固回路

**Feature Branch**: `main`（本次未创建新分支）

**Feature Directory**: `specs/013-memory-consolidation-loop`

**Created**: 2026-10-06

**Status**: Draft

**Input**: User description: "记忆巩固回路：离线 sleep-time 管线，维护空闲窗口、管理面手动 API 与记忆量阈值触发，仅 writer 管理面、域开关门控、scope 级互斥；MemoryDistiller 独立第四 Agent，四类提案与确定性降级；唯一生效路径为确定性裁决器，保护硬记忆、复验 scope、纠正链、配额及完整溯源；新增类型化链接图高级产出与依赖传播、可重建语境派生视图；知识候选与人工晋升；巩固运行审计；固定受益子集至少 6 条，沿 004 三重闸口；012 的 8 项 E2E 与既有全集无回归。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在工作之外安全启动巩固 (Priority: P1)

域管理员希望系统利用空闲时间整理积累的记忆，也能针对一个明确知识域手动启动并查看运行结果。日常检索、召回、记录记忆与会话开局无需等待巩固完成；同域已有运行时，新触发必须明确被拒绝。

**Why this priority**: 离线运行和单写纪律是全部巩固能力可安全接入现有系统的前提。

**Independent Test**: 对开启与关闭巩固的两个域，在 writer/reader 双实例上分别测试维护空闲、手动及量阈值触发；阻塞一次运行后并发再次触发，并在运行期间执行既有读写流程；覆盖运行资格数据库冲突、进程中断恢复，以及资格失效后旧持有者尝试提交。

**Acceptance Scenarios**:

1. **Given** 一个明确且开启巩固的 scope，**When** writer 管理面在维护空闲窗口、接收手动请求或发现未巩固记忆量达到配置阈值，**Then** 启动离线运行，返回或记录可查询的运行标识、触发原因和窗口，前台请求不等待该运行。
2. **Given** scope 未解析、存在歧义或 `memory_policy.consolidation_enabled=false`，**When** 维护空闲、手动或量阈值普通触发发生，**Then** 明确拒绝或记录跳过原因，不调用 Distiller、不产生普通巩固状态变化；不得回落到其他域或全库。关闭开关时的可信必要支持失效维护仅按 FR-002/020 的窄权限例外执行。
3. **Given** 同 scope 的运行仍在进行，**When** 任何来源再次触发，**Then** 三类触发经同一数据库活动资格唯一性约束返回可识别的忙碌拒绝与已有运行标识，不排队、不合并、不再启动；另一 scope 可独立获得运行资格。
4. **Given** reader 实例或普通 MCP 调用者，**When** 尝试启动巩固或晋升，**Then** 动作不可用或明确拒绝，知识内容、链接、派生视图及知识源均不发生写入。
5. **Given** 空窗口或一次失败/中断的运行，**When** 运行结束或执行恢复，**Then** 分别记录无输入结果或可审计的终态，并释放本域运行资格；后续合法触发可恢复工作。
6. **Given** 主开关关闭且没有新合格 episode，但已有派生结论的必要支持可证明失效，**When** 当前 writer 的可信维护/治理支持钩子触发 `deterministic_propagation`，**Then** 仍取得同一 scope 资格并完整复验 lease/token，经唯一裁决器只追加合法失效事件；窗口为 null，不调用 Distiller、不创建/归并记忆、不产出链接/语境/候选、不消费新输入。外部伪造该上下文不得获得权限。

### User Story 2 - 提炼经验并在模型故障时继续整理 (Priority: P1)

域管理员希望将窗口内尚未巩固的 episodic 记忆提炼为事实经验和操作经验，并减少可确定的重复、过期与冗余条目。模型只能提出建议；模型不可用或输出不合规则时，已能确定的去重、TTL 与归并仍然完成。

**Why this priority**: 巩固价值必须能被独立验证，且不把模型可用性变成记忆治理的前提。

**Independent Test**: 用包含有效、已巩固、隔离、下线、被替代、过期及重复 episodic 的窗口分别测试正常模型、超时、异常、畸形提案与无模型运行，对比确定性部分结果；覆盖时间边界、预算截断、部分失败后的检查点推进，以及与同域既有 semantic/procedural 的去重提案。

**Acceptance Scenarios**:

1. **Given** 同域窗口内有未巩固且可见的 episodic，**When** 选择输入，**Then** 输入集合仅包含合格条目及其对应权威事件，`quarantined`、`retired`、`superseded`、已到期、未完成写入和已成功巩固条目均不进入 Distiller 输入；同域既有合法 semantic/procedural 以独立参考集参与去重、合并和矛盾提案，不混作 episodic 提炼输入。
2. **Given** 可提炼的事实和操作经验，**When** Distiller 产出并经裁决批准，**Then** `extract_fact` 形成 `semantic`、`distill_procedure` 形成 `procedural`，新记忆标为 `distilled`，置信度采用通过范围及策略下限校验的 Distiller 自评值，保留来源记忆和事件链、支撑证据及推断元数据。
3. **Given** 可确定的重复或新旧矛盾，**When** `merge_duplicate` 或 `invalidate_contradiction` 提案通过裁决，**Then** 保留可追溯的归并/纠正关系，旧状态按既有生命周期退出默认消费；无足够依据的矛盾仅记录驳回，不能伪造解决结论。
4. **Given** 模型超时、供应商故障或输出未通过 Schema 校验，**When** 执行巩固，**Then** 非法模型输出不生效，去重、TTL 与确定性归并继续按同一规则执行，并报告降级原因和实际产出。
5. **Given** 全部提案被驳回、写入失败或预算只允许处理部分窗口，**When** 后续重试或推进检查点，**Then** 对应未成功输入仍可处理，未处理条目不被遗漏；仅生成提案或记录一次运行不得把输入误标成已巩固。
6. **Given** 合法 soft episode 没有知识库支撑证据但五元元数据完整，**When** 提炼 procedural 经验并通过裁决，**Then** 保留原 episode/事件来源，知识库证据明确为空并标注推断，不伪造证据或赋予人工晋升候选资格。

### User Story 3 - 让每项变化经过可审计裁决 (Priority: P1)

管理员需要知道每条提炼、归并、失效或链接建议为何通过或被拒绝，并确信推断不会单方面推翻已有硬记忆，也不会跨域、突破配额或切断历史。

**Why this priority**: 确定性裁决、硬记忆保护和完整溯源是宪法 VI/XII/XIII 的必要条件。

**Independent Test**: 对置信度边界、跨域目标、失效证据、断裂/循环纠正链、缺失源链、配额临界值及软硬冲突构造提案矩阵；在裁决与落库之间注入治理变更和投影故障。

**Acceptance Scenarios**:

1. **Given** 任一模型或确定性提案，**When** 申请生效，**Then** 唯一裁决器逐项验证适用置信度阈值、scope、最新状态、纠正链、配额、硬记忆保护和溯源；未通过者只有驳回审计，无成功巩固事件。
2. **Given** 高置信软提案与有效硬记忆矛盾，**When** 提案要求替代、失效或通过归并隐藏该硬记忆，**Then** 拒绝并记录原因；置信度高、重复次数多或模型声明有权限均不能构成硬证据。
3. **Given** 输入、目标或支撑证据在运行中被 retire、quarantine、supersede、撤销发布或移出可用范围，**When** 提交裁决结果，**Then** 再次校验并拒绝不再合法的变更，不以窗口快照绕过当前治理。
4. **Given** 已通过的提案，**When** 生效，**Then** 追加 `consolidate` 事件并同事务物化关系与本次链接/语境派生状态；相关同步投影尚未补齐时，遵守 012 未完成写入不可见规则，原可用状态仍可读取。
5. **Given** 记忆正文或模型输出包含工具调用、权限变更、关闭保护、跨域查询等指令，**When** 处理提案，**Then** 只按不可信数据与既定 Schema 处理，不改变提示控制、工具、开关或状态转换权限。

### User Story 4 - 根据固定对照结果决定默认开启 (Priority: P1)

维护者需要在预先冻结的至少 6 条巩固受益查询上比较巩固前后效果，并同时验证安全硬指标与原有能力。只有三组闸门全过才具备默认开启资格；质量未达标时保留可选能力和报告，默认关闭。

**Why this priority**: 巩固不能凭产出数量或主观观感进入默认路径。

**Independent Test**: 从同一权威输入快照构建未巩固与已巩固两组，使用相同查询、相关性标注、召回预算和环境评测；冻结提炼、失效/纠正、去重/合并各至少 2 条查询，首轮记录 LLM 响应，次轮以相同缓存重放且无模型网络调用；分别模拟质量不通过、安全不通过、缓存证据不完整与全通过情况。

**Acceptance Scenarios**:

1. **Given** 已冻结的至少 6 条结构性受益查询及其相关性标注，且提炼、失效/纠正、去重/合并各至少 2 条，**When** 比较巩固前后召回并以 005 响应缓存复现，**Then** MRR 与 nDCG 均相对提升至少 3%，命中率、Recall@K 和 Precision@K 均不下降，缓存证据完整且次轮无模型网络调用，才判质量闸通过。
2. **Given** 质量达标但存在跨域、隔离记忆进入窗口、软提案推翻硬记忆、源链缺失或候选自动入正身，**When** 验收，**Then** 硬指标闸失败并阻止发布，不以默认关闭替代修复。
3. **Given** 安全通过但质量未达标或缺少可复现证据，**When** 决定默认配置，**Then** `consolidation_enabled` 与链接关联扩展默认保持关闭，可选巩固能力和失败报告保留。
4. **Given** 新能力及故障降级用例，**When** 重跑 012 的 8 项 E2E、状态义务用例及 001–012 既有全集，**Then** 均按原口径无回归，原工具和旧客户端未显式启用新能力时保持兼容。

### User Story 5 - 使用可重建的关联与语境辅助召回 (Priority: P2)

调用者希望在记忆正文之外获得有关联依据的邻接记忆与简明语境，同时始终能区分确定性关系和模型推断。管理员需要在来源变化、删除或回滚后恢复一致的关联和语境，而不改写事实。

**Why this priority**: 类型化链接与语境派生视图补足关联导航和 GEM C3 依赖传播，但必须保持投影身份与受益门控。

**Independent Test**: 用同域依赖链、普通关联、重复边、跨域边和被撤回节点，检查生成、裁决、关闭/开启关联扩展、删除传播、回滚及非空重建；比对正文和 provenance，并在其他召回输入固定时验证语境字段有无不改变候选或排序，重建/回滚的模型调用次数为 0。

**Acceptance Scenarios**:

1. **Given** Distiller 产生有方向、有类型且有完整依据的链接建议，**When** 宽模式、当前域记忆链接词表及裁决校验通过，**Then** 形成可定位的类型化边，标明 `deterministic` 或 `llm_proposed`、置信度与产出运行；同一 `(from, to, relation_type)` 不重复生成有效边，词表外建议明确驳回。
2. **Given** 关联扩展默认关闭或未过受益闸门，**When** 正常召回，**Then** 保持既有直接召回行为，声明记忆链接词表不会自动开启扩展或文档图检索；三闸通过且域策略允许开启后，扩展结果仍遵守请求 scope、状态、事实时间和既有数量、内容与超时预算。
3. **Given** 依赖链上游被纠正、撤回、隔离或下线，**When** 下游派生记忆或关联结果被消费，**Then** 不把已失效支持当成有效依据；依赖传播可追溯，不沿普通关联任意使无关记忆失效，不让图环或高扇出突破预算。
4. **Given** 一条可用记忆，**When** LLM 生成的 `context_digest`、`keywords` 通过净化、Schema 校验及裁决，**Then** 摘要字符串与关键词列表仅用于展示、导航，不参与 embedding、候选召回、查询改写、过滤或排序，不修改正文、事实、信任等级或纠正链，不被包装成独立证据或控制指令。
5. **Given** 原本非空的链接和语境投影被清空，且运行审计已超过 TTL，**When** 从权威事件重建或回滚后重放，**Then** 直接恢复事件中的具体批准内容，无需再次调用模型即可恢复对应已批准版本的非空投影、来源链、scope 分布与指纹，包含逐字段一致的摘要、关键词和生成版本。
6. **Given** 巩固已生成有效 semantic/procedural，源 episode 仅因本次归并被 supersede，随后正常 TTL 归档/墓碑或管理面 purge，**When** 读取与重建派生结果，**Then** 历史源链仍完备，未声明实时依赖的结果不因来源退出默认读取而自行失效；确有必要支撑被撤销或声明实时依赖失效时才沿对应规则传播。

### User Story 6 - 人工将候选知识送入既有摄入流程 (Priority: P2)

域管理员可以发现高置信且有已发布硬证据锚定的 semantic 候选，检查原始记忆和巩固来源后，显式将其送入知识源摄入流程。标记候选、运行巩固或达到阈值都不会自动改变知识库正身。

**Why this priority**: 候选可以沉淀经验，人工晋升保留可信语料的治理边界。

**Independent Test**: 对符合与不符合候选条件的记忆检查标记；比较巩固前后知识源清单；由 writer 管理面晋升一次并跟踪摄入任务、来源指针、失败与重复请求。

**Acceptance Scenarios**:

1. **Given** active semantic 满足候选置信度阈值，且每条所需硬证据仍存在、同域、已 published 并通过逐条归因复验，**When** 裁决候选资格，**Then** 记录 `promote_candidate_at` 及依据；无锚、低置信或其他 kind 不获该标记，`distilled` 不因此变成 `hard`。
2. **Given** 候选已经标记，**When** 巩固、阈值触发或维护再次运行，**Then** 不自动创建知识源、发布版本或修改已有正身内容。
3. **Given** 管理员在 writer 管理面明确选择同域候选并执行晋升，**When** 资格复验通过，**Then** 创建知识源摄入任务，遵循既有上传、解析、版本与发布纪律；保留原记忆，追加指向任务及后续知识源/版本的晋升记录。
4. **Given** 摄入失败、重复晋升请求或候选已失效，**When** 查询或重试晋升，**Then** 明确显示失败/已有任务/资格失效状态，不伪称已发布，不静默重复创建相同晋升任务，不删除原记忆。

### User Story 7 - 查看巩固成本、裁决和失败轨迹 (Priority: P2)

管理员可以按域和运行检查窗口、输入、提案、裁决、产出、成本和降级，并区分成功、无变化、部分完成与失败。短期运行报告清理后，已生效的记忆仍保留长期来源和可重建依据。

**Why this priority**: 可审计结果让管理员判断巩固效果、失败原因及消耗，避免把部分成功当成全部完成。

**Independent Test**: 查询正常、空窗口、全驳回、降级、部分失败和中断运行；执行 7 天运行态 TTL 清理，再验证事件、记忆、链接和来源可恢复。

**Acceptance Scenarios**:

1. **Given** 任一已受理运行，**When** 管理员查看报告，**Then** 能找到 `run_id`、scope、窗口、输入事件、提案、逐项裁决理由、输出记忆、`provider_usage` 和明确状态，区分模型失败与确定性部分成功。
2. **Given** 运行记录达到运行态保留期限，**When** maintenance 清理，**Then** 只清理到期运行态数据，保留清理审计，不删除权威事件、有效记忆或链接，不破坏 `created_by_run` 的长期来源可解释性。
3. **Given** 整体运行在部分提案已生效后中断，**When** 恢复或再次处理窗口，**Then** 按已提交事件识别完成输入，不重复产出已批准记忆/边，不丢失尚未完成输入，报告准确反映已完成部分。

### Edge Cases

- 窗口边界采用 `[上次巩固检查点, 本次冻结观察点)` 的系统观察时间；首次从该域最早待处理来源事件起选，开始含、结束不含。同一观察时间按来源事件 ID 稳定排序，恰在边界的输入不被重叠选入；预算截断、失败或驳回条目仍保留原窗口及来源版本的待处理资格，检查点推进不得漏处理。事实有效时间过滤仍沿用 012。显式无 scope、歧义 scope、跨 scope 窗口均拒绝。
- 初选后发生 quarantine、retire、supersede、TTL 到期、证据撤销或配额占满：提交前复验，失效提案驳回，不扩大窗口或绕过保护。
- episodic 已过 TTL 时可由既有确定性治理处理，但正文不得送入 Distiller；该治理不会因模型故障或巩固开关关闭而停止。
- 空输入、无提案、全驳回、部分通过均有明确结果；不得把无产出运行或失败运行当成输入已巩固。
- 输入正文和派生摘要中的注入指令、凭据、伪造 scope/置信度/证据/系统角色必须沿用净化和控制隔离；新生成正文也必须经过既有写入安全校验。
- 缺失来源、提案源输入记忆/事件 ID 不在已选集合、循环/断裂纠正链、跨域目标、未知关系类型，以及缺失、非有限、越界或低于策略下限的置信度均驳回；置信度恰等于下限时仅通过该项校验，不豁免其他裁决。不得自动抬高低置信值。同域现有目标、本次已批准产出及支撑证据引用按各自规则复验，不把它们误当成必须在 episodic 输入集中的引用。不能靠模型补造源链或权限。
- 完全重复与语义近似必须区分；硬锚不一致的条目不能仅因文本相似归并，同正文但元数据冲突仍遵守 012 的重复提交冲突规则。
- 高置信矛盾提案、多条软提案投票、模型自称确定性或伪造权限均不能单方面让硬记忆失效。
- 同域手动、维护和量阈值触发竞争以数据库活动资格记录上的 scope 部分唯一索引裁定，冲突明确返回已有运行；运行异常退出与重试不得造成并行生效、永久占锁或重复产出。资格过期、释放或被恢复接管后，旧持有者不得继续提交；跨域运行互不占用对方资格。不能在追加式运行审计历史上用未更新的运行中状态永久占锁。
- 链接自环、依赖环、重复三元组、高扇出和无效端点均有确定性处理；扩展失败只降级本次增强，不放宽 scope 或既有读取过滤。
- 关系键匹配宽模式但不属于当前域记忆链接词表，或词表版本/方向/依赖语义已变更时，提交前复验并驳回不再合法的建议；不得按关系名称猜测实时依赖或自动批准矛盾失效。012 已有 `evidence`/`supersedes` 基础边仍沿原契约生成和重放，不受新增高级词表缺省影响。
- 运行审计 TTL 与有效链接寿命不同；清理报告不能级联删除有效边、来源链或阻断重建。
- 模型无法生成或语境输出校验失败时，不保存未批准字段，已有合法批准版本继续按当前治理可见，新记忆无语境字段仍可正常读取；只保存模型/提示版本或指纹而未保存具体摘要和关键词，不满足可重建性。
- 晋升请求处理途中失效、重复提交、摄入失败或未发布时，原记忆和任务轨迹保留，不报告正身已更新。
- 基线指标为零、模型输出波动、环境波动或评测标签变化不能伪造通过；非有限相对增益不计通过，需可计算的固定对照证据。
- 评测缓存缺失、损坏、版本不匹配或次轮发生真实模型调用时，保留报告并标记可复现证据不完整，不宣称过闸；成功和失败响应均须重放，不能只缓存有利结果。缓存命中不计为真实供应商调用/用量，首次调用成本与重放成本分开呈现。

## Requirements *(mandatory)*

### Functional Requirements

#### 触发、运行资格与输入窗口

- **FR-001**: 巩固 MUST 采用离线 sleep-time 模式，由 writer 管理面承接维护循环空闲窗口、手动 API 和未巩固记忆量阈值三类触发；检索、召回、写记忆与 `start_work` 不得同步执行或等待 Distiller，量阈值只请求离线工作。
- **FR-002**: 每次运行 MUST 明确且仅属于一个已解析 scope。维护空闲、手动与量阈值普通巩固 MUST 校验域 `memory_policy.consolidation_enabled` 和显式配置，关闭时拒绝手动运行并记录自动触发跳过原因。唯一例外是可信 writer 维护/治理支持失效钩子构造的 `deterministic_propagation`：开关关闭或普通巩固配置缺失时仍可取得同一 scope 资格，仅凭当前可复验支持失效证明批准 `invalidate_contradiction`/v2 `invalidate`，window=null，不调用 Distiller，不允许 create/merge/link/context/candidate 或源消费；完整 writer lease、scope 互斥、token fencing、硬保护、裁决与事件发布纪律仍适用。REST/MCP/记忆正文/模型输出不能选择或构造此维护上下文。reader 与普通 MCP 不得提供巩固/晋升生效通道；域策略变更沿用既有管理权限与内置档案治理。
- **FR-003**: 系统 MUST 实施覆盖整个运行及其恢复阶段的 scope 级互斥：三类触发共用独立运行态资格记录，在活动资格上使用 scope 部分唯一索引保证同域至多一个持有者，不仅依赖进程内应用锁。同域正在运行时再次触发 MUST 在取得资格的数据库冲突处显式拒绝并提供已有 `run_id`，不能静默排队、合并或启动另一运行。资格记录与 append-only `consolidation_runs` 审计分离，可续期、释放及故障恢复；每次权威提交 MUST 在同一提交边界内原子复验活动资格、未过期状态、持有者、`run_id` 与资格版本，防止资格失效或接管后旧持有者写入。失败与中断 MUST 可恢复并释放资格，恢复同一运行也须取得独占资格；不同域资格独立，资格状态不成为记忆事实来源。

  FR-002 的可信支持失效维护共用上述资格、冲突拒绝、恢复及最终提交 fence，不另设并行写通道。
- **FR-004**: 巩固窗口 MUST 按单 scope 的半开观察时间区间 `[上次巩固检查点, 本次冻结观察点)` 定义，首次从该域最早待处理来源事件起选；输入仅限窗内当前 active、有效、未到期、写入已完成且尚未成功巩固的同域 episodic。条目上限仅用于窗内预算分批，不以每批 N 条重新定义窗口；按来源事件观察时间及事件 ID 稳定排序。四态选取遵守下表；窗口边界、批次顺序、输入记忆及对应 `input_event_ids` MUST 可审计且可复现。

| 当前状态 | episodic 提炼输入 | 既有 semantic/procedural 参考目标 |
|----------|------------------|----------------------------------|
| `active` | 满足有效、未到期、写入完成及未成功巩固条件时纳入 | 满足有效、未到期及写入完成条件时可纳入，不受新输入时间窗限制 |
| `quarantined` | 排除 | 排除 |
| `retired` | 排除 | 排除 |
| `superseded` | 排除 | 排除 |

- **FR-005**: 已巩固判定 MUST 以已成功提交的权威结果及其来源事件为依据，不依赖会过期的运行审计。失败、全驳回和无产出不得消费输入；部分成功只确认已生效部分，同一来源版本重试不得重复产出。检查点推进 MUST 保留预算截断、失败、驳回及未处理来源版本的待处理资格及原窗口，后续运行先复验并重试仍合格的待处理条目；该资格可由长期来源/结果轨迹恢复，不依赖运行审计 TTL，也不等同于对忙碌触发排队。
- **FR-006**: 窗口检查点规则、批次条目上限、量阈值、适用置信度阈值、候选阈值与离线资源预算 MUST 为显式可校验策略值，运行保存生效值或版本；无效值拒绝，模型输出不得修改这些值。缺少新策略配置时自动巩固和关联扩展保持关闭。

#### 独立提案与降级

- **FR-007**: `MemoryDistiller` MUST 是符合既有 `AgentBase` 契约的独立第四子类，提供 `ROLE`、`NODE_SCHEMA`、`execute` 和确定性 `fallback`；不进入 005 检索编排状态机，不拥有直接写事件、投影、域策略或知识源的能力。
- **FR-008**: `NODE_SCHEMA` MUST 覆盖 `extract_fact`、`distill_procedure`、`merge_duplicate`、`invalidate_contradiction` 四类提案及必要的来源、目标、置信度、证据和关联链接建议；前两类目标 kind 分别为 semantic/procedural，模型提炼的 confidence MUST 为 Distiller 对该提案的自评有限数值，范围 `[0,1]`，不以源 episodic 的最小值或加权聚合替代。链接是受校验的附属建议，不以任意新 action 绕过四类契约；未知 action、越界值和缺失必填字段视为校验失败。确定性 fallback 的输出也须通过适用提案 Schema，适用置信度须标明确定性规则及依据，不伪称模型自评，也不因 AgentBase 已返回降级结果而跳过验证。
- **FR-009**: 巩固输入正文 MUST 作为不可信数据；模型输出仅作为经 Schema 校验的裁决器输入，不得控制工具、权限、scope、提示策略、执行跳转或开关。生成正文、链接描述与派生语境 MUST 复用 012/008 的脱敏、注入隔离与分级写入约束。
- **FR-010**: 模型超时、异常、不可用或 Schema 失败 MUST 触发确定性降级；去重、TTL 与可证明等价的归并仍照常处理，且全部有状态效应的操作仍经过适用裁决及既有治理规则。相同输入、策略与时钟条件下确定性部分结果一致；失败模型输出不得混入生效结果。

#### 唯一裁决与权威生效

- **FR-011**: 确定性裁决器 MUST 是所有巩固记忆、归并/失效、候选标记、链接与语境产出的唯一生效批准路径；模型和确定性候选均不得绕过裁决直写。每项提案 MUST 记录接受/驳回、适用规则、理由和受影响对象。
- **FR-012**: 裁决 MUST 检查适用置信度阈值（含阈值边界）、来源/目标/支撑证据的 scope 与当前合法状态、单指针 supersede 链完整性及无环性、当前域配额、硬记忆保护和必填溯源链；模型提炼自评 confidence MUST 为 `[0,1]` 内有限数且 `confidence >= 生效策略下限`，缺失、非有限、越界或低于下限均拒绝，不自动补值或抬高。通过置信度校验不代替来源与证据复验，也不赋予硬记忆处置权。提交前 MUST 再核验变化，配额不足时显式拒绝，不静默驱逐。同域现有合法 semantic/procedural MUST 可作为独立参考集参与去重、合并和矛盾提案，不受 episodic 新输入时间窗限制，也不得混作 episodic 提炼输入；参考选取与目标版本可审计，参考数量、来源数量/链深与提案数均受已声明预算约束，仍遵守硬记忆保护。
- **FR-013**: 软提案 MUST NOT 单方面替代、失效、隐藏、降级或通过归并间接推翻硬记忆。硬记忆只能被有新硬证据且通过逐条归因复验的合法 hard 替代，或由 writer 管理面明确人工处置失效；硬锚定 distilled 产出与确定性归并本身均不构成此授权。LLM 置信度、多数投票、频次或自称权限均不能替代硬锚。
- **FR-014**: 成功提炼 MUST 保存 `provenance=distilled`、来源记忆 ID/事件链及派生关系，并包含来源、置信度、模型版本或确定性规则版本、时间、支撑证据五元元数据；模型提炼保存经批准的原始自评置信度及自评来源标识、裁决下限与策略版本，确定性提案保存规则版本和置信依据。源记忆置信度及来源版本可追溯供审计，不聚合为模型提炼置信度；hard 来源的 confidence 沿 012 保持 NULL。每条源链可回到原 episode/事件，已有知识库证据逐条可定位。合法软来源无知识库证据时该字段明确为空，仍保留非空记忆源链、推断标记且无晋升资格，不伪造证据。多源历史溯源与单指针纠正链、实时依赖必须区分；正常来源归并/TTL 不自动否定其已批准派生结果，也不能由高置信或硬锚自动提升事实权威。
- **FR-015**: 归并与矛盾失效 MUST 遵守 012 supersede/有效期纪律，保留旧正文与事件；没有确定性支持的矛盾不得生效。归并保留来源并区分等价重复与元数据冲突，不能新增多父纠正链或改变 scope。
- **FR-016**: 只有裁决批准的产出才可追加 `consolidate` 事件，并与关系、本次链接与语境派生投影同事务物化；事件 MUST 保留六轴元数据、运行/行动者标识、输入事件、裁决依据、产出和完整重放材料。事件追加或事务投影失败不得报告成功；跨存储同步投影仍沿用 012 失败不可见、恢复后开放及旧状态可见规则。
- **FR-017**: 驳回 MUST 记录运行审计，不产生该提案的成功 `consolidate` 事件或改动事实/候选/链接/语境。局部失败 MUST 可与已提交产出区分，恢复不得重复批准已提交提案；012 普通 TTL/治理不因巩固禁用或模型故障停止。

#### 类型化链接与语境派生投影

- **FR-018**: 本 Feature MUST 扩展既有投影③ `memory_links` 的高级产出契约，至少表达 from/to、`relation_type`、`provenance ∈ deterministic|llm_proposed`、confidence、`created_by_run` 与 scope；保留唯一性 `(from, to, relation_type)`。新增高级链接的 `relation_type` MUST 沿 010 使用宽模式 `^[a-z][a-z0-9_]{0,62}$` 的裸词表键，不采用全局闭合枚举；具体允许类型、方向及关系语义由域档案中的记忆链接词表声明并版本化，词表 MUST 与文档图词表区分，避免声明记忆类型时意外开启文档提取/检索。两端 MUST 当前合法且同域，形态非法、词表外类型和无依据自环拒绝；不得另建独立链接事实源。此新增词表校验仅治理高级建议，012 已有 `evidence`/`supersedes` 基础溯源/纠正边沿原契约生成和重放；010 `graph_edge`/`soft_relation` 的既有硬软边契约保持兼容。
- **FR-019**: 链接建议 MUST 由 Distiller 产出并由裁决器批准，裁决及提交前均按当前域记忆链接词表复验成员、方向和关系语义，记录生效词表版本；匹配宽模式本身不赋予产边资格。标记为 `deterministic` 的关系必须有可复验的确定性依据，不能根据模型自述认定。`llm_proposed` 永久保留推断标记及五元元数据，不能冒充硬关系或已发布事实。
- **FR-020**: 链接 MUST 支持 GEM C3 依赖传播：域记忆链接词表 MUST 明示有向实时依赖、历史溯源与普通关联的语义分类及传播方向，不能仅从 `derived_from`、`contradicts`、`elaborates` 等名称猜测传播或状态权限；必要事实/证据被明确否定或已声明实时依赖失效后，不得继续消费依赖该支持的过时派生结论。历史源 episode 仅因成功归并被替代或正常 TTL/purge 退出默认读取，不自动使永久 semantic/procedural 失效。传播需保留源链与影响记录，不跨域、不提升权威、不直接改投影；需要改变记忆有效状态时仍走受裁决的权威事件。环和高扇出按确定性去重、终止和预算处理。

  读取安全过滤及 FR-002 的可信必要支持失效维护不受普通巩固开关关闭影响；失效维护只可沿原永久 lineage 产生受裁决的 invalidate，不能借传播生成新事实或派生附件。
- **FR-021**: 正常召回的关联扩展 MUST 默认关闭，仅在巩固受益、安全及回归三闸通过且域策略允许后具备开启资格，并与域巩固门控联动；声明词表或生成链接不等于允许进入默认召回。扩展节点和端点逐项复验 scope、status、有效时间及已有读取约束，不能复活退出默认消费的记忆。增强失败时报告降级并返回原过滤下的可用结果，保持既有读取数量、字数和超时上限。隔离评测副本可为证明受益显式启用候选扩展，但不得据此改变正常域策略或省略安全裁决。

  正式读取 MUST 从受信任部署配置指定的只读闸口登记文件加载已审阅报告，验证固定报告哈希、scope、数据及代码/策略/词表/提示/Schema/模型/召回配置绑定、有效期与三闸语义；仅 `consolidated_candidate_expansion` 报告可授权链接扩展。报告生成不自动登记或修改策略；缺失、篡改、错域、旧版本、过期或不可读取的证明一律不授权，继续原合法直接召回。生产路径不得从请求、正文、模型或上传目录选择证明，具体契约见 [gate-proof.md](contracts/gate-proof.md)。
- **FR-022**: 巩固 MUST 支持由 LLM 生成 `context_digest` 摘要字符串和 `keywords` 关键词字符串列表，经既有净化、Schema 校验及确定性裁决批准后生效，字段长度/数量按显式预算约束；记录来源记忆/事件及生成模型、提示/Schema 版本。字段 MUST 仅用于摘要展示和导航，不参与 embedding、候选召回、查询改写、过滤、排序或 RRF 加权；导航访问仍遵守 scope、状态和事实有效时间。字段不改变正文、事实、kind、provenance、证据和纠正链，不赋予新行动权限，不作为独立证据。模型不可用或输出未获批准时保留已有合法版本，无派生字段时既有读取仍可用，不影响确定性巩固降级。
- **FR-023**: 链接图和语境字段 MUST 是只读、可重建的派生投影；具体已批准链接、摘要文本、关键词列表、来源链和生成版本及裁决依据 MUST 长期保存在 append-only 权威事件中，不能仅保存模型/提示版本、指纹或短期运行报告。从同一日志重放 MUST 直接恢复相同已批准版本的内容，无需再次调用模型。离线重新生成新语境版本也须经裁决与事件记录；删除、隔离、supersede、retire 和回滚正确反映各端点的默认可见性，历史源链保留且依赖有效性按 FR-020 判定。验收 MUST 清空原本非空投影并清理到期运行审计后重建，再验证回滚/重放；对应版本逐字段内容、scope、源链、数量与指纹一致，重建及回滚模型调用次数为 0。

#### 候选与人工晋升

- **FR-024**: 仅 active、达到候选置信度阈值且具备同域 published 硬证据锚定的 semantic 可经裁决标记 `promote_candidate_at`；证据 MUST 逐条复验存在、scope、发布状态、内容归因和位置。候选标记是事件派生状态，不自动升级 provenance，也不产生正身知识。
- **FR-025**: 知识候选自动写入、修改或发布知识库正身的次数 MUST 为 0。晋升 MUST 是 writer 管理面人工显式动作，重验候选、scope、当前证据与权限后创建知识源摄入任务，走既有上传管线和版本发布纪律；普通 MCP、Distiller、定时触发和量阈值不能发起晋升。
- **FR-026**: 晋升 MUST 保留原记忆，并通过权威轨迹追加晋升指针和行动者/请求标识，至少可追踪摄入任务及其后续知识源、版本和结果。任务创建不等于发布成功；同一候选版本的重复请求返回已有任务，失败可沿既有管线重试，不能删除源记忆或重复生成正身内容。

#### 运行报告与保留

- **FR-027**: `consolidation_runs` MUST 记录 `run_id`、scope、window、`input_event_ids`、proposals、adjudications、`output_memory_ids`、`provider_usage`、status、创建/到期时间，并能关联触发原因、生效策略、请求与模型/规则版本，以及资格取得、释放和恢复轨迹；已记录的运行观察 MUST append-only，不 UPDATE 既有窗口、输入、提案、裁决、产出或状态，进度与终态通过追加记录保留轨迹。活动资格唯一索引 MUST NOT 放在这些不可更新的历史审计记录上；到期审计清理不得释放仍有效的运行资格。删除仅允许 FR-029 的到期清理。

  审计 MUST 区分普通 `trigger=idle/manual/volume, execution_context=distiller_window` 与内部 `trigger=support_maintenance, execution_context=deterministic_propagation`；后者 window=null、input_event_ids=[]，单独保留历史来源及当前支持失效 trigger/proof，不能冒充新提炼输入或人工请求。
- **FR-028**: 管理面 MUST 支持按 scope/运行查看报告与候选，并区分运行中、成功、无变化、降级/部分完成、失败和中断；已接受、拒绝和失败数量与实际权威结果一致。模型 Schema 失败或供应商错误需可见，费用/用量记录沿 006 既有口径，缺失用量明确标记而非伪造零成本。
- **FR-029**: 运行审计 TTL MUST 沿运行态默认 7 天与既有可配置保留纪律；只由 maintenance 清理到期数据并留清理审计。TTL 不影响永久权威事件、有效记忆、链接、候选/晋升轨迹和完整来源链；`created_by_run` 的历史身份与重放不得依赖未过期的运行行，不得级联删除有效投影。

#### 受益闸门与兼容

### Key Entities *(include if feature involves data)*

- **Consolidation Window**: 单 scope 的 `[上次巩固检查点, 本次冻结观察点)` 半开观察时间区间、预算内稳定排序的 episodic 输入及权威事件集合；保留未成功来源版本的待处理资格。既有 semantic/procedural 是独立同域参考集，不属于提炼输入；保存选取依据、目标版本和策略，按四态表排除非法状态。
- **Consolidation Proposal**: 四类动作之一，含来源、目标、期望 kind、置信度、支撑证据与附属链接/语境建议；是未授权建议而非事实或指令。
- **Adjudication**: 单项提案的确定性裁决，含规则与版本、复验依据、通过/驳回原因及影响对象；是巩固唯一批准结果。
- **Consolidate Event**: 012 已定义的事件类型，本 Feature 新增其受裁决产出路径；保存源事件链、六轴元数据、产出和可恢复的链接/语境材料。
- **Distilled Memory**: 经批准提炼的 semantic/procedural 等记忆，模型提炼置信度来自 Distiller 自评并通过裁决器策略下限校验；保留置信来源、下限/策略版本、推断身份、五元元数据及原 episode/证据源链，不因候选资格改变权威。
- **Typed Memory Link**: 投影③中的同域有向关系，三元组唯一；高级类型使用宽模式及域记忆链接词表，携带词表版本、方向、实时依赖/历史溯源/普通关联语义、确定性/推断 provenance、置信度和产出运行标识。
- **Context Derivative**: LLM 生成并经批准的 `context_digest` 字符串、`keywords` 字符串列表及对应来源/生成版本；具体内容长期保存于权威事件并直接重放，是仅供摘要展示/导航的可重建语境投影，不参与召回或排序。
- **Knowledge Candidate and Promotion Pointer**: 经裁决的候选时间/依据，以及人工晋升产生的任务、知识源、版本和结果指针；原记忆仍保留。
- **Consolidation Run**: 7 天默认 TTL 的运行态审计，包括窗口、提案、逐项裁决、产出、供应商用量与状态；长期正确性不依赖其在线寿命。
- **Consolidation Runtime Eligibility**: 与追加式运行审计分离的 scope 运行态资格，活动记录由部分唯一索引保证同域唯一；关联 run_id、持有者、资格版本及到期状态，供续期、释放、恢复和提交原子复验，不是记忆事实来源。
- **Benefit Gate Report**: 提炼、失效/纠正、去重/合并各至少 2 条的固定子集巩固前后质量、硬指标、回归、成本和环境证据；含缓存及版本指纹、成功/失败重放统计、模型真实调用/用量，以及是否具备默认启用资格的判定。
