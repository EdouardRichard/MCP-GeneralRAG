## User Scenarios & Testing *(mandatory)*

### User Story 1 - 只在显式信号下附加相关记忆 (Priority: P1)

外部 Agent 在检索知识库时，可以顺带拿到与当前会话或当前上下文相关的既有记忆；但只做普通知识检索的调用者，感知不到任何变化。

**Why this priority**: 附加层是 014 的主能力面，而"纯 scope 检索零破坏"是它能进入既有默认检索路径的唯一前提。

**Independent Test**: 对同一 scope 与 query，分别以"不传新参数""只传 session_id""传 session_id + memory_context"三种方式调用主检索，比较响应字段集合与序列化字节；再以记忆召回不可用、超时、全部低于阈值三种场景验证主检索结果完全不变。

**Acceptance Scenarios**:

1. **Given** 未显式提供 session_id 与 memory_context 的检索请求，**When** 调用主检索，**Then** 响应不含任何新增字段，且与 014 之前相同输入逐字节一致；纯 scope 检索不触发记忆附件。
2. **Given** 显式提供 session_id 或 memory_context，**When** 调用主检索，**Then** 在 `evidence[]` 之外并列返回 `related_memories[]`（默认 top 3、上限 5），每条带 provenance 标注与 `injection_flags`；`evidence[]` 的内容、顺序与字段不变。
3. **Given** 记忆召回不可用、超时或候选全部低于 `attach_min_score`，**When** 主检索本身成功，**Then** `related_memories` 为空数组（三者同生共死，不缺席）、`memory_notice` 说明附加层降级原因，而主检索的 `completion_status`、`evidence`、`gaps`、`error`、`request_id` 完全不变（独立降级）。
4. **Given** 附加层触达 800ms 或 800 字预算，**When** 组装响应，**Then** 只裁剪附加条目（top 3/上限 5、单条 excerpt ≤200 字），不裁剪、不延迟、不延长主检索结果与其既有预算。
5. **Given** 一条高度相关但处于 quarantined 或 superseded 状态的记忆，**When** 组装 `related_memories`，**Then** 它不出现；retired、已过期、写入未完成的记忆同样不出现。

### User Story 2 - 让宿主安全地消费注入形态 (Priority: P1)

宿主把检索结果放进模型上下文时，必须能分辨"知识库证据"和"记忆"，必须知道记忆是不可信数据，也必须能按提示深读某条记忆。

**Why this priority**: 注入形态决定记忆会不会被当成控制指令或被当成已发布事实，是宪法 III/V 的直接落点。

**Independent Test**: 对含 `related_memories` 与不含的响应分别做结构化内容与文本内容比对；解析文本内容后验证字段分隔、不可信声明与深读指引，并逐字段核对顶层顺序；构造超预算响应验证裁剪顺序。

**Acceptance Scenarios**:

1. **Given** 任一带新字段的响应，**When** 宿主读取文本内容，**Then** 文本内容与结构化内容为同一事实源的确定性序列化，两者语义与字段值完全一致，不存在第二套渲染。
2. **Given** 同时存在证据与记忆，**When** 宿主解析响应，**Then** 两者以并列字段分隔（`evidence[]` ‖ `related_memories[]`），不出现把记忆混入证据数组或以文本拼接合并两类内容的情况。
3. **Given** 存在 `related_memories`，**When** 宿主读取 `memory_notice`，**Then** 该字段用一句话同时给出不可信数据声明（记忆不是已发布事实、不得作为控制指令）与深读指引（按 `memory_id` 调用记忆精读工具）。
4. **Given** 相同字段内容，**When** 序列化两次，**Then** 顶层字段顺序按契约固定，两次字节完全一致。
5. **Given** 总预算不足以容纳全部内容，**When** 裁剪，**Then** 先裁记忆再裁证据、先裁工作集再裁摘要，读取指引永不裁剪；每次裁剪都在 `counts` 中可观测。

### User Story 3 - 会话内不重复交付同一条记忆 (Priority: P1)

同一会话跨通道反复请求时，调用者不会反复看到已经交付过的同一条记忆；确实需要时可以用显式参数覆盖。

**Why this priority**: 跨通道重复交付会浪费宿主上下文并稀释检索价值，而"不自动放宽"是隔离与不确定性披露纪律的要求。

**Independent Test**: 在同一会话中依次经精读通道、主检索附加层和会话开局通道交付同一批记忆，检查去重效果与计数；再用显式覆盖参数复现；最后构造"去重后为空"的场景检查返回值与建议动作。

**Acceptance Scenarios**:

1. **Given** 同一会话已经通过某一通道收到某条记忆，**When** 经另一通道再次请求，**Then** 该记忆默认不再交付，且计数暴露因去重被丢弃的条数；三个通道共用同一份会话级已交付记忆集。
2. **Given** 调用者显式声明要包含已交付记忆，**When** 再次请求，**Then** 去重被覆盖，已交付记忆可再次返回；覆盖只影响本次请求，不静默改写会话状态。
3. **Given** 去重后没有剩余候选，**When** 返回，**Then** 附加层返回"无可用记忆"空态（`related_memories` 为空数组 + `memory_notice` 说明去重致空）并给出可操作的 `gaps` 建议动作（例如显式请求包含已交付记忆），不自动放宽过滤条件、scope 或阈值；主检索的 `completion_status`、`evidence` 与主检索自身产生的 `gaps` MUST NOT 被该空态改写（与 FR-004 独立降级一致）。
4. **Given** 已交付记忆集记录超过其短保留期，**When** 新一轮请求到达，**Then** 过期记录不再参与去重；该记录是运行态数据，不是记忆事实来源。
5. **Given** 会话跨越多个知识域，**When** 去重，**Then** 去重不改变单域隔离，也不把 A 域记忆交付给 B 域请求。

### User Story 4 - 用确定性工作集续接上一个会话 (Priority: P1)

Agent 在一个新会话开局时，可以拿到由知识域与最近会话派生的续接包：还没了结的事项、最近发生了什么、以及相关操作经验。

**Why this priority**: 跨会话续接是 3.0 的核心用户价值，也是"多会话连续性"对照闸门的被测对象。

**Independent Test**: 在域 A 构造开放与已关闭的 episodic、近期活动与 procedural 经验，分别以有无会话标识请求会话开局包，比对包体内容、字节稳定性、预算与装箱顺序；重复请求验证字节一致与零模型调用。

**Acceptance Scenarios**:

1. **Given** 可解析的 scope 与相关会话，**When** 请求会话开局包，**Then** 工作集包含三类派生内容：未决事项（没有 `valid_to` 的开放 episodic）、近期活动、相关 procedural 教训；每类都保留 provenance 标注，作用域由包级 `scope` 承载（单作用域、不越域）。
2. **Given** 相同输入与相同数据/策略版本，**When** 重复请求，**Then** 工作集字节完全一致；组装过程不调用任何模型，无模型进控制路径。
3. **Given** 工作集与摘要同时超预算，**When** 装箱，**Then** 沿既有上下文装箱纪律（确定性排序、跨类去重、显式裁剪决策、预算上限），摘要优先于工作集，读取指引永不裁剪，裁剪在计数中可观测。
4. **Given** quarantined、superseded、retired 或已过期记忆，**When** 组装工作集，**Then** 均不进入；未决事项判定只看开放度与有效性，不因相似度或频次放宽状态过滤。
5. **Given** 未显式请求新组装形态的既有调用，**When** 请求会话开局包，**Then** 既有包体形态与其字节稳定性不被打破。

### User Story 5 - 用固定对照结果决定续接能力是否默认可用 (Priority: P1)

维护者需要在预先冻结的至少 15 条多会话连续性任务上比较"带记忆"与"无记忆"的效果，只有达标才允许进入默认路径。

**Why this priority**: 记忆续接不能凭主观观感或条目数量进入默认路径（宪法 X）。

**Independent Test**: 从同一权威输入快照构建两个库内容一致的对照组，使用相同查询、环境与预算，唯一差异是记忆可用性；分别模拟达标、不达标与证据不完整三种情况。

**Acceptance Scenarios**:

1. **Given** 已冻结的至少 15 条固定查询，覆盖跨会话任务断点续接、上次决策召回、教训生效、偏好应用四类，且含中文，**When** 评测，**Then** 每条有可定位的确定性判据、可观测的"任务完成"二值定义与相关性标注，AI 生成结果经人工审核通过；闸门判定不依赖 LLM-judge。
2. **Given** 两组使用相同库内容与相同召回配置，**When** 对照运行，**Then** 唯一启用变量是记忆可用性；基线组禁用相关参数（不携带会话标识与记忆上下文），不得通过更换语料制造差异。
3. **Given** 带记忆组相对无记忆组，**When** 判定，**Then** 命中率/冗余度等指标相对提升 ≥3%，或有一组预先冻结的显式任务完成判据证明更优；未达标则保留可选能力并默认关闭。
4. **Given** 基线为零、环境波动或评测证据不完整，**When** 判定，**Then** 不得以不可计算或不可复现的证据宣称过闸；报告保留逐查询差异、延迟与成本。
5. **Given** 连续性达标，**When** 检查既有检索能力，**Then** 既有检索全集与旧评测集按各自口径无回归，非延迟指标在既有容差内。

### User Story 6 - 让宿主直读只读的文件投影 (Priority: P2)

宿主或人工审计可以不经 MCP 直接读取按知识域与记忆分型组织的只读文件树，获得每条记忆的原文与元数据、域记忆摘要和目录导航。

**Why this priority**: 文件投影提供零集成成本的直读能力，但它只能是派生视图，必须严格只读且可全量重建。

**Independent Test**: 触发一次记忆写入，检查文件树、frontmatter 与正文；清空文件投影后从权威日志全量重建并比对指纹；尝试绕过校验直接写文件，验证被拒绝。

**Acceptance Scenarios**:

1. **Given** 一个已解析的知识域，**When** 记忆写入完成并刷新，**Then** 文件树的路径按作用域与记忆分型组织，每条记忆一个文件，frontmatter 含记忆标识、分型、provenance、置信度、有效时间、会话、证据引用、状态与被替代指针，正文为记忆正文原文。
2. **Given** 同一作用域目录，**When** 读取，**Then** 存在域记忆摘要文件（巩固后重建）与目录导航文件；两者互相一致且不引入新的权威内容。
3. **Given** 文件投影被清空或损坏，**When** 从权威日志全量重建，**Then** 路径、frontmatter、正文、摘要与导航均恢复一致，重建过程不调用模型。
4. **Given** 任何调用者（含模型、正文内容或管理请求），**When** 尝试绕过校验直接写文件投影，**Then** 被拒绝；投影写入只能来自既有权威事件与校验路径。
5. **Given** 文件投影内容与权威日志不一致，**When** 系统给出事实或状态判定，**Then** 一律以权威日志为准，文件投影不构成事实源。
6. **Given** 记忆写入发生在关键路径上，**When** 刷新文件投影，**Then** 刷新异步进行、不进关键路径，其失败不影响写入响应与读取可用性。
7. **Given** 既有按数字作用域/投影标识组织的修订目录，**When** 清空、重建或删除消费层，**Then** 既有目录、既有落盘校验器与其重建/回滚报告路径不受影响；两层内容冲突时以权威日志为准，且对外契约明确标注消费层为宿主直读面。

### User Story 7 - 在三宿主上冒烟并保证全集无回归 (Priority: P2)

发布负责人需要证明工作集续接与文件投影直读在目标宿主上可用，并证明既有能力零回归。

**Why this priority**: 契约零破坏与目标宿主可用性是发布门槛（宪法 X，沿用既有参考客户端惯例）。

**Independent Test**: 在各目标宿主的 MCP 配置下完成会话开局续接与文件投影直读；重跑 012/013 的 E2E 与既有检索全集、旧客户端响应比对。

**Acceptance Scenarios**:

1. **Given** 目标宿主（DSH / Claude Code / ChatGPT App）的 MCP 配置，**When** 执行工作集续接与文件投影直读，**Then** 按各宿主的既定阻塞策略给出结论并记录可复现证据。
2. **Given** 012 与 013 的既有 E2E，**When** 全量重跑，**Then** 按原验收口径无回归。
3. **Given** 旧三工具客户端与旧评测集，**When** 重跑与比对，**Then** 不携带新参数的响应逐字节不变，旧评测集不被破坏。
4. **Given** 记忆能力整体不可用，**When** 调用新参数，**Then** 宿主仍能拿到完整正确的主检索结果（fail-open）。

### Edge Cases

- 只传 `memory_context` 而不传 `session_id`：附加层仍触发，但无会话去重语境；此时阈值取"宁缺勿滥"的保守档，低置信软记忆不附加。反之只传 `session_id` 而无上下文时同样按保守档处理。
- `memory_context` 与查询语义相同时可用于召回；两者都是不可信输入，必须经既有轻量注入检测并记 flags，不得改写成控制指令，也不得借其选择 scope、阈值、过滤或状态。检测 MUST 先于任何使用（含召回与排序）发生；高风险内容按既有隔离语义处理，只降级附加层、不得让主检索失败或改变其字段；检测自身失败不得阻塞检索，也不得被当作放宽过滤或阈值的依据。
- 附加层信号在调用中被显式提供但值为空/非法：按参数错误处理，不放宽为"未触发"，也不静默降级为带附件。显式传入 `null` 与省略等价（视为未提供：不触发、不报错）；空串、非 UUID 的 `session_id`、超长或非字符串的 `memory_context` 按参数错误处理。运行时无法区分"显式 `null`"与"省略"，因此不得依赖该区分。
- scope 未解析、歧义或跨域：沿用双轨错误与 candidates，绝不回落，附加层与工作集组装不得绕过。
- 记忆条目超过上限或字数：按 top 3（上限 5）与 800 字裁剪，excerpt ≤200 字并标记 truncated；裁剪必须可观测。
- 附加层与主检索共享总超时预算：附加层超时不超过 800ms 且不得把主检索推过其既有总超时；主检索自身超时时按原错误路径返回，不因附加层而改变错误码。并发执行下，主检索完成或超时必须同时回收附加层任务（MUST NOT 遗留悬挂任务、MUST NOT 因等待附加层而延后响应）。
- 记忆召回部分可用（部分投影失败）：按部分降级返回可用条目并标注失败路径，不改变主检索状态，不扩大 scope。
- 同一记忆同时是证据锚定来源：仍必须在两个字段中分别呈现各自语义，不得因共享来源而合并字段或复用证据标识。
- 会话级已交付记忆集跨通道并发写入同一会话：最终去重结果必须唯一且可解释，不产生"同一条记忆在同一响应内出现两次"。
- 去重与 include_delivered 交互：显式覆盖只放宽去重，不放宽 scope、状态、有效期或阈值过滤。
- 工作集未决事项判定：只有"无 `valid_to` 的开放 episodic"算未决；semantic/procedural 不因缺少 `valid_to` 被误判为未决事项。
- 工作集有效期与"已过期"判定：一律相对**数据派生的 `snapshot_at`**（该作用域内 `max(observed_at)`）计算，MUST NOT 使用墙钟；否则"已过期排除"（FR-023）与"相同输入跨时刻字节一致"（FR-021）不能同时成立。
- 主检索处于 agentic 编排路径（`AGENTIC_RETRIEVAL_ENABLED=true`，`search_knowledge` 走 005 状态机）时：014 的触发门控、独立降级与逐字节兼容口径与确定性路径一致——未显式提供新参数时响应仍与 014 之前逐字节一致；附加层与工作集 MUST NOT 绕过不可信隔离与状态过滤，MUST NOT 进入或改变编排状态机的节点、排序与预算。
- 工作集"最近会话"解析与无会话记录：显式会话标识优先，否则只在本作用域内按活动时间选取最近的非空会话，且最多回溯 1 个会话；MUST NOT 使用跨作用域会话数据、MUST NOT 因会话解析引入第二个作用域。作用域内没有任何带会话标识的记忆时，工作集 MUST 仍返回未决事项与相关 procedural 教训，近期活动为空并在计数中标注"无会话记录"，MUST NOT 报错、MUST NOT 回退全库或扩大作用域。
- 工作集成员的来源记忆随后被纠正、撤回或下线：工作集反映当前权威状态，不复活已退出默认消费的记忆。
- 文件投影：作用域或分型名包含路径分隔、超长、大小写冲突或非 ASCII 时，路径归一化必须确定性且不逃逸根目录；同一记忆在纠正/替代后，其文件状态与被替代指针一致，归档态不残留可消费正文。
- 文件投影两层并存：既有修订目录继续按数字作用域/投影 ID 组织并被既有校验器与回滚路径消费；消费层按 slug/kind 组织并独立重建。清空、重建或删除消费层不得改变既有目录、既有落盘校验器或既有重建/回滚报告；两层内容冲突一律以事件日志为准，不得以任一层的现状推断记忆状态。
- 文件投影扩容：条目数量增长导致消费层文件数或目录深度变化时，路径形态、frontmatter 字段集合与导航内容必须保持契约稳定，不得因规模变化改变既有文件路径。
- 文件投影与并发写入：刷新与重建并发时不得产生半个域的可消费中间态；投影不完整时读路径仍以权威日志为准。
- 文件投影漂移与修复：检测到消费层与权威日志漂移时，必须按作用域清空并从权威日志全量重建并出报告；读路径不得就地修复、不得依据漂移内容做事实或状态判定；修复失败必须保留失败标记且不影响权威读取与既有修订目录。
- 文件投影中的 frontmatter 正文含 YAML 敏感字符或凭据：按既有脱敏与转义纪律输出，不得因投影泄露凭据或破坏解析。
- DIGEST.md 在巩固未运行或巩固被禁用时：保持可重建或明确为空态，不伪造摘要内容。
- 连续性评测：不同宿主的上下文预算不同，评测必须固定环境与预算；宿主压缩导致的信息丢失不得算作记忆能力失败。
- 对照闸门：基线组若因缺少记忆而回答"无法确定"应按判据记为未完成，不得记作命中；两组不得共享会话态或已交付记忆集。
- 三宿主冒烟在宿主不可用时：按既定策略记录兼容状态或跳过，不得把"未执行"记为通过。
- 新字段与旧客户端：旧客户端若严格校验响应字段集合，新增字段只在显式信号下出现，因此不得改变其既有行为；未知字段处理不得成为新契约的隐含依赖。

## Requirements *(mandatory)*

### Functional Requirements

#### 主检索增量与触发

- **FR-001**: 主检索 MUST 新增两个可选输入（会话标识与记忆上下文）。仅当调用者显式提供其中至少一个时，才允许附加记忆；两者都未提供时必须不发生任何记忆读取、不产生任何新增字段，行为与字节与本次增量之前完全一致。本规格 MUST NOT 提供"轻量记忆提示"第二档：未显式提供新参数的检索（含纯 scope 检索）MUST NOT 出现通知、提示或任何记忆相关字段；冷启动续接 MUST 由会话开局工作集（FR-020）承担。
- **FR-002**: 主检索输出 MUST 新增可选的相关记忆数组、条件通知字段与计数；`related_memories` 与 `evidence` MUST 为并列独立字段，任何情况下 MUST NOT 混装、合并、复用同一数组或以文本拼接合并（混装违反证据可定位性语义）。显式信号触发且主检索 `completion_status != "failed"` 时，`related_memories`、`memory_notice`、`counts` 三者同生共死：`related_memories` 恒在（可为空数组）、`memory_notice` 恒为对象（MUST NOT 为 `null`）、`counts` 恒在；未触发时三者一个都不出现。
- **FR-003**: 每条附加记忆 MUST 携带 provenance 标注（分型、信任等级、置信度适用性、证据引用、推断元数据）与 `injection_flags` 随行；不得只返回正文。记忆条目的可定位性由 provenance/`evidence_refs`/有效期承担，因此 MUST NOT 携带 `source_position`、`source_version` 或 `relevance_score` 等证据定位字段（两套定位语义不得混写；混写即违宪 IV 语义）。`hard` 条目 MUST 复用既有逐条归属复验（硬锚），无锚、复验失败或状态不可见者 MUST NOT 进入 `related_memories` 或工作集；`soft`/`distilled` 条目 MUST 携带五元推断元数据（`source`/`confidence`/`model_version`/`time`/`supporting_evidence`），缺失即整条不合格。
- **FR-004**: 附加层 MUST 独立降级：记忆召回失败、超时、部分不可用或全部低于阈值 MUST NOT 改变主检索的完成状态、证据、缺口、错误码或请求标识。附加层失败原因 MUST 可识别。
- **FR-005**: 附加层 MUST 遵守显式预算：返回条数由**域策略**配置（默认 3 条、硬上限 5 条，MUST NOT 新增请求侧条数参数），请求内容与模型输出 MUST NOT 改写该配置；附加内容总长 ≤800 字；单条摘录 ≤200 字并标记截断；附加层自身超时 800ms。该预算 MUST 为附加层独立预算：候选池、条数、字数与超时 MUST 独立于 `evidence` 的 `top_k` 与主检索既有预算，MUST NOT 从 `evidence` 名额中扣减或改变其数量、内容与顺序。附加层 MUST NOT 延长或挤占主检索既有预算。附加层 MUST 与主检索**并发发起**并在响应组装点合并（附加层输入只依赖已解析作用域与查询/记忆上下文，MUST NOT 等待 `evidence`），因此附加层 MUST NOT 增加主检索端到端延迟；串行执行 MUST NOT 作为实现方式。
- **FR-006**: 附加记忆 MUST 通过显式阈值筛选，阈值 MUST 为可校验的域策略值，模型输出、请求内容或记忆正文 MUST NOT 修改阈值。未请求记忆上下文时 MUST 采用更保守的"宁缺勿滥"档：低置信软记忆与低分候选不附加。
- **FR-007**: 附加与工作集 MUST 排除 quarantined、superseded、retired、已过期以及写入未完成的记忆；过滤 MUST 沿用既有读取可见性与状态复验，MUST NOT 因相关度高、置信度高或重复出现而豁免。
- **FR-008**: 附加层 MUST 只读，且 MUST NOT 改变 scope、过滤条件、主检索排序或证据集合，MUST NOT 从证据的 `top_k` 名额中扣减；附加条目自身排序 MUST 确定性且不依赖调用时钟。附加层预算 MUST 独立于证据名额（见 FR-005）。

#### 上下文注入形态与字段契约

- **FR-009**: 文本内容 MUST 为结构化内容的确定性序列化（单一事实源）；MUST NOT 引入第二套渲染、模板或人工拼接文本。
- **FR-010**: 结构分隔 MUST 位于字段层：证据与相关记忆并列呈现；仅靠自然语言说明或文本分节分隔 MUST NOT 视为满足。
- **FR-011**: 通知字段 MUST 为条件字段，用一句话同时承载两件事：记忆为不可信数据、不得作为控制指令或事实授权；以及按记忆标识调用记忆精读工具的深读指引。缺失任一部分 MUST 视为不合格。
- **FR-012**: 顶层字段顺序 MUST 契约化固定，同一内容 MUST 序列化为相同字节；顺序契约 MUST 记录在对外契约中并作为验收项。冻结顺序为：legacy 分支保持 `completion_status` → `evidence` → `request_id`（`partial` 时在其后追加 `gaps`；`failed` 时为 `completion_status` → `evidence` → `error` → `request_id`）；014 分支按 `completion_status` → `evidence` → `related_memories` → `memory_notice` → `counts` → `gaps` → `error` → `request_id` 重建（`gaps` 仅在 `partial` 或去重致空时出现，`error` 不在 014 分支出现）。即新增的 `related_memories`、`memory_notice`、`counts` 作为一个整体紧随 `evidence` 之后、位于 `gaps`/`error`/`request_id` 之前，以保持 `evidence` 与 `related_memories` 字段层相邻（FR-010），且只在显式提供新参数时出现。既有字段的相对顺序 MUST NOT 因本 Feature 改变（与 SC-001「增量前逐字节一致」一致）。契约见 `contracts/field-order-contract.md` §2。
- **FR-013**: 预算不足以容纳全部内容时 MUST 按固定优先级裁剪：证据优先于记忆；摘要优先于工作集；读取指引永不裁剪。每次裁剪 MUST 在计数中可观测。
- **FR-014**: 计数 MUST 至少暴露返回条数、候选条数、因预算被裁剪条数、因跨通道去重被丢弃条数、因状态不可见被过滤条数；计数取值 MUST 与实际权威结果一致。
- **FR-015**: 记忆内容与查询/上下文输入 MUST 作为不可信数据处理；MUST NOT 改变提示控制、工具、权限、开关、scope 或状态转换。`memory_context` MUST 在进入任何召回、打分、排序或拼装之前先经既有注入检测并记录 flags（检测先行），MUST 只进入不可信数据层（与查询同级），MUST NOT 进入系统提示或任何控制指令；高风险片段 MUST 在面向模型的文本中按既有隔离语义处理，且 MUST NOT 因此使主检索失败（独立降级）。检测自身失败 MUST NOT 阻塞主检索，也 MUST NOT 被当作放宽过滤或阈值的依据。仅提供记忆上下文而未提供会话标识时 MUST 采用保守档。

#### 会话级已交付记忆集

- **FR-016**: 系统 MUST 维护会话级已交付记忆集，作为短保留期的运行态记录，登记各通道每次交付的记忆标识（含精读通道、主检索附加层、会话开局通道），供跨通道去重共用。
- **FR-017**: 默认 MUST 对已交付记忆去重；显式声明包含已交付记忆时 MUST 覆盖去重，且覆盖只作用于本次请求。
- **FR-018**: 去重导致结果为空 MUST 返回"无可用记忆"空态——`related_memories` 为空数组、`memory_notice` 说明去重致空，并在 `gaps` 给出可操作的建议动作；该空态 MUST NOT 改写主检索的 `completion_status`、`evidence` 或主检索自身产生的 `gaps`（FR-004 独立降级）；MUST NOT 自动放宽过滤、scope、阈值或有效期。`no_evidence` 仅描述主检索的证据层结果，MUST NOT 被用作记忆层去重结果的表达。
- **FR-019**: 已交付记忆集 MUST 不构成事实来源、MUST NOT 改变记忆状态或显著性以外的事实字段、MUST NOT 跨域泄露；记录过期后 MUST 不再参与去重。

#### 会话开局工作集组装器

- **FR-020**: 会话开局包 MUST 扩展工作集组装器，按已解析作用域与最近会话派生三类内容：未决事项（没有结束有效期的开放 episodic）、近期活动、相关 procedural 教训。每类 MUST 保留 provenance 标注；作用域由包级 `scope` 承载（单次组装只服务一个已解析作用域，条目 MUST NOT 越域）。"最近会话" MUST 只在已解析作用域内部解析：调用方显式提供会话标识时以其为准，否则 MUST 取该作用域内记忆条目中按活动时间最新且带非空会话标识的那一个会话；MUST NOT 使用跨作用域的会话新近度，MUST NOT 借会话解析扩大作用域。近期活动 MUST 只取自该 1 个会话；未决事项 MUST 不受会话限制（取该作用域全部开放 episodic）；procedural 教训 MUST 按作用域取。作用域内无任何带会话标识的记忆时，MUST 仍确定性返回未决事项与该作用域的相关 procedural 教训，近期活动 MUST 为空并在计数中可观测。新组装形态 MUST 由调用方**显式请求**（新增可选参数或新增 `include` 取值，默认关闭）；未显式请求时 MUST 返回既有包体形态。有效期与"已过期"判定 MUST 相对数据派生的 `snapshot_at`（该作用域内 `max(observed_at)`）计算，MUST NOT 使用墙钟（否则与 FR-021 的字节一致冲突）。
- **FR-021**: 组装 MUST 为纯函数确定性代码，MUST NOT 让模型进入控制路径；相同输入与相同数据/策略版本 MUST 产生相同包体字节。MUST NOT 落盘包快照。
- **FR-022**: 装箱 MUST 沿既有上下文装箱纪律：确定性排序、跨类去重、显式裁剪决策、预算上限与既有三档预算；摘要优先于工作集；读取指引永不裁剪。
- **FR-023**: quarantined、superseded、retired 与已过期记忆 MUST NOT 进入工作集；未决事项判定 MUST 只依据开放度与有效性，MUST NOT 由相似度、频次或模型判断决定。"已过期"与有效期判定基准 MUST 为数据派生的 `snapshot_at`（见 FR-020），不使用墙钟。
- **FR-024**: 工作集扩展 MUST 为增量：未请求新组装形态的既有调用 MUST 保持既有包体形态与字节稳定性（包括今天已传 `session_id`、`task_hint`、`agent_id` 或既有 `include`/`budget` 取值的调用；`session_id` MUST NOT 充当新形态的隐式开关）；包体 MUST NOT 含请求标识或生成时刻等易变字段。

#### 文件投影

- **FR-025**: 文件投影 MUST 位于 `<DATA_ROOT 父目录>` 下按作用域（slug 归一化）与记忆分型组织的只读**消费层**文件树，每条记忆一个文件；消费层根目录由 `MEMORY_CONSUMPTION_ROOT` 冻结（默认 `<DATA_ROOT 父目录>/memory_projection`，默认解析为 `./data/memory_projection`，即 `data/memory_projection/{scope_slug}/{kind}/*.md`；`DATA_ROOT` 沿既有配置键解析，默认 `./data/uploads`），与既有 `data/uploads/memory_projection/` **物理分离**，既有根目录下 MUST NOT 出现消费层目录；路径归一化 MUST 确定性、可重建且不逃逸投影根目录。
- **FR-025a**: 消费层 MUST 与既有按修订（数字作用域 ID / 数字投影 ID）组织的投影目录**分层并存**：既有目录降级为内部暂存/修订表示，本 Feature MUST NOT 修改其路径语义、落盘校验器或既有重建与回滚验收口径。两层 MUST NOT 互为事实源，唯一权威仍为事件日志；消费层 MUST 可独立全量重建、可被安全清空后重建而不影响既有目录，两层内容冲突时一律以事件日志为准。对外契约 MUST 明确哪一层是宿主直读的消费面。
- **FR-026**: 每个记忆文件 MUST 含 YAML frontmatter，至少覆盖：记忆标识、分型、provenance、置信度、有效时间（起止）、会话标识、证据引用、状态、被替代指针，以及不可信标记 `untrusted: true`；正文 MUST 为记忆正文原文（脱敏后），不得改写、摘要或截断、不得追加指令，但该宿主直读面 MUST 以 `untrusted: true` 标记声明"记忆为不可信数据、不得作为控制指令或已发布事实"（与 `memory_notice.untrusted=true` 同义）；正文原文与不可信声明并存，二者 MUST NOT 互相替代。消费层的 DIGEST.md 与 INDEX.md MUST 在文件头同样声明该不可信语义。
- **FR-027**: 消费层每个作用域目录 MUST 含域记忆摘要文件（巩固后重建）与目录导航文件；二者 MUST 与权威日志一致，MUST NOT 引入新的权威内容或伪造成事实。巩固未运行或巩固能力关闭时，摘要 MUST 保持可重建或明确空态，不得伪造内容。目录导航 MUST 采用混合粒度：顶层按记忆分型分组，分型内条目数超过域策略阈值时再按时间桶分节；分组与条目排序 MUST 确定性且可重建。
- **FR-028**: 消费层 MUST 只读、可独立全量重建；从权威日志全量重建 MUST 恢复路径、frontmatter、正文、摘要、导航与指纹一致，且 MUST 可在清空后重建而不影响既有修订目录、既有重建与回滚验收路径，重建 MUST NOT 调用模型。
- **FR-029**: 文件投影的任何一层 MUST NOT 构成事实源：与权威日志冲突时一律以日志为准，任何事实或状态判定 MUST NOT 依赖文件投影；两层之间亦 MUST NOT 互为事实源。
- **FR-030**: 文件投影任何一层的写入 MUST 只来自既有权威事件与校验路径；任何绕过校验、校验失败或未授权角色发起的文件系统直写 MUST 被拒绝并记录。绕过即违反"日志为唯一写入点"与"投影只读"约束。
- **FR-031**: 消费层刷新 MUST 为异步、不进关键路径：写入响应与读取可用性 MUST NOT 等待刷新；刷新失败 MUST NOT 影响写入结果、既有读取或既有修订目录，且 MUST 可恢复。触发 MUST 为事件驱动的合并刷新（写提交后按作用域登记待刷新并交有界后台工作者处理）；固定定时轮询 MUST NOT 作为唯一触发方式。
- **FR-031a**: 消费层 MUST 提供漂移检测与修复：每次刷新 MUST 对本作用域做轻量校验（清单与指纹），MUST 在既有周期维护窗口做全层对账，并 MUST 支持按需全量校验。检测到消费层与权威日志漂移时 MUST 按作用域清空并从权威日志全量重建、输出可核验报告；读路径 MUST NOT 就地修复，MUST NOT 依据漂移内容做事实或状态判定。
- **FR-032**: 删除、撤回、纠错、隔离、归档与回滚 MUST 传播到消费层；墓碑与已退出默认消费的记忆 MUST NOT 在消费层残留可消费正文。传播 MUST NOT 改动既有修订目录的既有语义与验收口径。

#### 评测、闸门与兼容

- **FR-033**: MUST 提供至少 15 条固定多会话连续性评测查询，覆盖跨会话任务断点续接、上次决策召回、教训生效、偏好应用四类，含中文（`zh` ≥2 条），由 AI 生成并经人工审核；查询、判据与相关性标注 MUST 在评测前冻结，MUST NOT 事后替换或删除失败查询。期望锚点 MUST 采用跨环境稳定机制（作用域 slug + 定位前缀/结构锚点），MUST NOT 依赖运行时生成的 `memory_id` 作为唯一锚点（同快照内一致性校验除外；沿用 011 固定集纪律 FR-007）；人工审核记录 MUST 随数据集入库并沿用 `_meta.review_status`/`review_notes`/`grounded_source` 形态。每条查询 MUST 附带冻结的确定性判据（必需结果项与禁止项）与可观测的"任务完成"二值定义，判据 MUST 能在无模型条件下重算复现；LLM-judge 输出 MUST NOT 作为闸门判据，仅可进入诊断报告。
- **FR-034**: 对照闸门 MUST 比较带记忆与无记忆两组：两组库内容、查询、预算与环境一致，唯一启用变量为记忆可用性；基线组 MUST 禁用相关参数。判据 MUST 为相对提升 ≥3%，或一组预先冻结的显式任务完成判据；基线为零或证据不完整时 MUST NOT 宣称过闸。基线组禁用参数的具体形式 MUST 为：对照臂策略显式关闭记忆附加与工作集扩展，且调用不携带会话标识与记忆上下文；两组 MUST 由同一权威快照恢复并要求库内容指纹一致；基线响应 MUST 断言零新增字段。"任务完成" MUST 定义为该查询预冻结的全部必需结果项均命中且各带可定位引用、且无越域或无效项；基线回答"无法确定" MUST 记为未完成。闸门判定 MUST NOT 依赖 LLM-judge 输出；若运行 LLM-judge，其结论 MUST 只进诊断报告并标注为非闸门证据。
- **FR-035**: 达标结论 MUST 同时满足质量达标、安全硬指标通过（跨域泄漏为零、schema 合法率 100%、provenance 完备率 100%、隔离记忆泄漏为零）与既有无回归；未达标时 MUST 保留可选能力并默认关闭，不得以默认关闭替代修复硬指标失败。
- **FR-036**: 验收 MUST 覆盖双会话连续性（前一会话记录 → 后一会话工作集续接 → 断点信息完整恢复）、主检索携带会话上下文时相关记忆附注且不混证据、带记忆与无记忆对照达标、既有检索评测集无回归四类 E2E。
- **FR-037**: 目标宿主冒烟 MUST 覆盖 DSH、Claude Code 与 ChatGPT App 的工作集续接与文件投影直读，并按既定参考客户端阻塞策略给出结论；未执行 MUST NOT 记为通过，宿主不可用 MUST 记录兼容状态。
- **FR-038**: 012 与 013 的既有 E2E 以及既有检索全集 MUST 按原验收口径重跑无回归；旧三工具、旧客户端与旧评测集 MUST 逐字节不变，新增字段只在显式提供新参数时出现。
- **FR-039**: 错误码 MUST 只增不删；新参数非法、scope 未解析/歧义、附加层超时与记忆不可用 MUST 有可区分且不破坏既有错误映射的表达；MUST NOT 引入会回落或放宽过滤的新语义。

### Key Entities *(include if feature involves data)*

- **Related Memory Attachment**: 附加层交付的单条记忆，含标识、分型、provenance、置信度适用性、证据引用、推断元数据、摘要、状态、注入标记与附加原因；与知识库证据字段并列、语义独立。
- **Memory Notice**: 条件通知字段，一句话同时承载不可信数据声明与深读指引，并说明附加层降级或裁剪原因。
- **Delivered Memory Set**: 会话级短保留期运行态记录，登记各通道已交付的记忆标识，用于跨通道去重与去重计数；不是事实来源。
- **Working Set Package**: 会话开局包的续接部分，含未决事项、近期活动、相关操作经验与截断标记；由作用域与最近会话确定性派生。
- **Memory File Projection**: 按作用域 slug 与分型组织的只读消费层文件树，每条记忆一个带 frontmatter 的文件（含不可信标记 `untrusted: true`），另有域记忆摘要与目录导航；派生自权威日志、可独立全量重建，与既有按数字 ID 组织的修订目录分层并存且不互为事实源。
- **Memory Continuity Query**: 固定评测查询，含类别（断点续接/决策召回/教训生效/偏好应用）、跨环境稳定的期望锚点（作用域 slug + 定位前缀/结构锚点，不以运行时生成 ID 为唯一锚点）、评测前冻结的确定性判据（必需结果项与禁止项）、可观测的"任务完成"二值定义、相关性标注与语言，以及随库入库的人工审核记录（`_meta.review_status`/`review_notes`/`grounded_source`）；判据可在无模型条件下重算，用于带记忆与无记忆对照。
- **Continuity Gate Report**: 对照评测报告，含环境与版本指纹、逐查询两组差异、延迟与成本、判据达成情况、硬指标与回归结论，以及是否具备默认启用资格；基线组禁用参数与库内容一致性证据 MUST 在报告中可见，LLM-judge（若运行）MUST 只作为诊断项标注、不得作为过闸依据。
